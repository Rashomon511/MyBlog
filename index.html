Polestar / Skill Lifecycle

AgentEvalTelemetryLLM-as-Judge

项目描述

面向企业内部业务场景建设 Agent Skill 工厂，让业务人员可以通过自然语言生成 ERP / 业务 Skill，并让 Skill 从生成、评测、发布、监控到优化形成闭环。项目重点解决三个问题：Skill 生成质量不可控、Agent 可能伪造工具调用结果、上线后缺少可观测与自愈机制。

项目职责

  • 参与设计 Intent、Generate、Eval-Cases、Eval-Run、Publish、Monitor、Report / Optimize 等生命周期流水线，把 Skill 从“生成脚本”升级为可治理资产。
  • 设计 Stage 3 caseInputs + 真 spawn 评测机制，由系统真实执行 baicao api call，并采集 stdout、exitCode、duration，避免 Agent 只在上下文中伪造 toolCalls。
  • 建设 normal、edge、error、security、off_topic、multi_turn 等评测类型，结合 Critical 必过、Pass@K、Baseline Regression 和 rubric 评分保障质量。
  • 引入 LLM-as-Judge 对开放式结果进行结构化评价，同时保留确定性断言，避免全部依赖模型主观判断。
  • 落地 Fix-Suggester 菜单式自愈和 Telemetry 埋点，覆盖成功率、耗时、Token、工具链、cohort 与内容指纹。
结果 沉淀 7 阶段生命周期、6 类 Eval 用例与 Critical/Pass@K/Baseline Regression 门禁；真实 spawn 采集 stdout/exitCode/duration，降低 Skill 人工评审、回归和上线风险。

bianque-erp-cli / baicao

CLIKBSQLite FTS5BM25

项目描述

面向 ERP 能力网关建设统一 CLI，同时服务开发 / 运维人员和 Agent 宿主。CLI 为认证、能力发现、参数模板、API 调用、KB 检索和故障诊断提供标准入口，让 Agent 不再直接猜接口、猜参数、猜调用方式，而是通过可审计、可测试、可恢复的工具链访问 ERP 能力。

项目职责

  • 设计 Agent 友好的命令面，覆盖 api list/read/call/call-template、catalog search、invoke、kb search/resolve/doctor 等核心链路。
  • 设计结构化输出、参数模板和错误提示，让 Agent 能稳定读取命令结果，并在缺参、鉴权失败、能力不存在时获得可恢复信息。
  • 参与 KB v4 六层知识架构：scenario -> workflow -> bridge -> clarify -> capability -> response，使用 SQLite FTS5 + BM25 + 路由增强替代裸向量 RAG。
  • 推进 Local-first、Graphify 12 表、manual / derived / view 三层隔离、SHA-256 内容寻址、commit log、manifest_root_hash 和 C1-C6 恢复合同。
  • 建设 7 套 234 条用例门禁，覆盖 KB 检索、能力发现、参数构造和真实 API 调用；其中 KB 检索套件 153 / 153 通过。
结果 建设 7 套 234 条发布门禁，其中 KB 检索套件 153/153 通过；统一 api/kb/catalog 命令面，减少 Agent 接口试错、参数构造和人工排障成本。

医药自营供应链 ERP AI 友好型架构改造

ERPMonorepoiframeAI Coding

项目描述

负责医药自营供应链 ERP 系统中财务、订单、工单、客户、营销等重要业务模块开发。随着组内推进前后端一体化，原 ERP 600+ 页面集中在一个仓库，公共依赖和全局状态耦合严重，存在升级影响面大、回测成本高、上线后回滚慢的问题；同时，超大仓库上下文也会降低 AI 生成率和 Agent 改造效率。因此主导将 ERP 改造成按业务模块拆分、可独立部署、可灰度切换、可快速回滚的 AI 友好型架构。

项目职责

  • 梳理财务、订单、工单、客户、营销等模块边界，设计“ERP 壳子 + 独立子模块”的接入方式，主仓只维护公共组件逻辑与统一入口。
  • 编写按页面、模块、多模块拆分的自动化脚本，替代人工迁移，降低 600+ 页面拆分时的人力成本、遗漏风险和重复回归成本。
  • 将各业务模块拆分为可独立部署的 Monorepo 子仓，通过 iframe 形式接入 ERP；所有 iframe 共享统一入口组件，支持新旧代码并存。
  • 设计新老路由共存和在线路由配置方案，同一模块内可在独立子模块与原页面组件之间切换，出现问题时可快速回滚。
  • 抽离通用业务组件和通用方法为 npm 包统一维护，将路由配置、页签配置线上化，避免各子模块重复维护公共依赖。
  • 通过 iframe 通信解决全局状态同步，包括页签状态、页面缓存、页面刷新、路由参数透传和数据更新后的页面切换。
结果 完成 600+ ERP 页面模块化拆分与灰度切换方案，支持 50+ 配置化页面、10+ 仓库组件复用；支撑采销/财务/订单线上化率达 80%/97%/100%，用户体验分由 2.9 提升至 4.2。

AIxcel - Excel 智能处理 Agent

PythonPandasWebSocketSandbox

项目描述

企业级 Excel 智能处理 Agent，用户通过自然语言提出分析、清洗、合并、多文件对比等需求，系统由 Agent 生成并执行 pandas 代码，通过 WebSocket 实时推送处理进度，最终输出 S3 文件或文本分析结果。项目重点是让非技术用户不用写脚本，也能完成复杂表格处理。

项目职责

  • 设计双层 LLM 架构：外层 AgentExecutor 决策是否调用 Excel Tool，内层 ExcelProcessor 负责生成和执行 pandas 代码，降低单层 Prompt 复杂度。
  • 采用 Structured Chat + JSON blob 兼容 GPT-4.1、GPT-4.1-mini、Doubao-deepseek-v3，并通过 handle_parsing_errors=True 支持格式错误自愈。
  • 实现 AgentProgressTracker + WebSocket 进度协议，将 intermediate_steps 转换为 percentage、step、iteration、chat_response 等前端可消费状态。
  • 建设 SafeOS + 线程池沙箱，限制文件和系统访问范围，支撑 Excel 分析、多文件对比、PDF 表格处理和图表生成。
结果 覆盖 Excel 分析、清洗、合并、多文件对比、PDF 表格处理、图表生成等 6 类场景；格式错误平均 2-5 轮自愈收敛，4 类 WebSocket 进度状态让处理过程可见。
